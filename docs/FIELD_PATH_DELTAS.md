# 递归字段路径增量

2026-10-24。下行差量已扩展到结构体、map 元素、list/数组元素内部的叶字段。
业务赋值写法不变，服务端比较已提交的前后图像，不依赖 Lua setter 的调用记录。

```lua
self.position.x=10
-- 路径 ["position","x"]，新值 10；不发送未变化的 y/z。

self.data.position.x=10
-- 路径 ["data","position","x"]，新值 10。

self.tasks['daily.1'].progress=10
-- 路径 ["tasks","daily.1","progress"]，新值 10。

self.items[64].count=2
-- 路径 ["items",63,"count"]，新值 2。
-- Lua 下标仍从 1 开始；线上下标从 0 开始。
```

路径组件带类型，字符串键与数字下标明确区分；`daily.1` 是一个完整 map 键，不会按点号拆成多层。
路径均相对客户端有权看到的顶层属性，属性级 ACL/AOI 过滤在生成补丁前完成。
不增加字段级权限，结构内部字段继续继承顶层可见范围。

## 合并与回退

- 固定结构递归比较有变化的字段；map 已存在的元素继续递归比较，新增键发送完整新值，删除键发送删除标记。
- 序列长度不变时可按下标递归到叶字段；长度变化时使用连续 splice，避免插入/删除后下标错位。
- 在每个子树比较递归编辑、整值替换、序列区间替换的编码成本，最终再与已有 FSA1/FSA2 表示比较。只有更小时才选择新表示。
- 因此，`position.x` 通常只发送 x；若 x/y/z 全部修改，发送整个 position 可能更省字节。
- 一次提交里同一路径改多次，只会根据最终状态生成差量；没有任何最终变化的字段不会重复发送。
- 首次订阅和重新获取快照仍全量发送可见属性；持久化仍保存完整 FSA1 图像。

这是值/字段差量，不是字符串内部字节差分；如果变化的叶字段本身就是 1 KB 字符串，仍需发送该字符串的新值。
也不保证逐条交付一份提交内部的中间业务操作。

## 协议与安全应用

FSA1 全量图像/属性替换、FSA2 顶层容器编辑继续可读；带字段路径的更新使用 **FSA3**。
FSA3 在每个编辑中增加有类型的路径，支持已有值替换、指定路径 map 的键编辑、指定路径序列的 splice。
根属性与被替换/删除的目标必须已存在，不会沿着不存在的路径自动创建容器。

每条记录仍受 1 MiB、4096 值节点、256 顶层属性/编辑上限约束。路径最多 8 段，与值嵌套深度共用原有深度 8 限制，
路径里的字符串键最多 127 字节且不含 NUL，下标范围 0..255。替换子树也必须符合所在深度的剩余空间。

接收端核对基准版本，在独立候选图像中解析路径与应用补丁，再校验合并后图像并一次发布。
缺版本、缺键、路径类型不符、越界下标、非法替换值或预算超限时，不会留下部分变化或推进版本号。
既有权限撤销、订阅代数、背压及观察者隔离机制不变。

旧读端不认识 FSA3，服务端与客户端/离线读取工具需要同步升级；当前没有能力协商。
默认上行 write/batch 现在也共用差量生成器，服务端在候选状态中应用后再检查权限、类型与业务规则。
固定请求 ID、缺失/不匹配基准的兼容回退见 [上下行共用差量](SHARED_ATTRIBUTE_DELTAS.md)。
连续上行修改仍可用 [batch](ATTRIBUTE_BATCHING.md) 减少提案和提交次数。

## 编码大小实测

Release GCC 14.2，Lua 开启、PostgreSQL 关闭；调用 `fsnet-container-benchmark wire 10`。
每个场景都将编码结果实际应用到副本，检查值等于完整目标图像。这是确定性编码大小对比，不是延迟或吞吐测试。
下表比较 FSA1 整属性替换与当前自适应编码，不是将旧版二进制和新版做运行速度对比。

| 场景 | 整属性 FSA 字节 | 当前差量 FSA 字节 |
| --- | ---: | ---: |
| nested_struct_1kb | 1111 | 54 |
| position_x | 67 | 48 |
| list_replace | 4146 | 52 |
| list_append16 | 4664 | 556 |
| map_add16 | 5200 | 805 |
| map_erase16 | 4008 | 191 |

`nested_struct_1kb` 保留 1024 字节未变 payload，只修改 `data.position.x`：1,111 → **54 字节**，
减少约 95.1%。`position_x` 为三个 double 的 vec3，仅修改 x。`list_replace` 为 128 个 Item 中只改一个 count，
当前只传 count 字段，其他场景保留已有 splice/map 编辑。
数值含 FSA 协议头、路径和值，不包含 FSN1、TCP/TLS 信封、请求/确认或首次快照。
[原始编码样本](benchmarks/field-paths-2026-10-24.json)。

```sh
cmake -S . -B /tmp/fsnet-fields -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=OFF
cmake --build /tmp/fsnet-fields --target fsnet-container-benchmark -j3
/tmp/fsnet-fields/fsnet-container-benchmark wire 10
```

原生测试覆盖 1 KB 大字段不进入单叶更新、vec3 单字段与密集回退、map 点号键/数字下标混合路径、深度 8 边界、
截断/非法路径、多个编辑中途失败无部分更新、FSA2 兼容以及 600 轮随机容器重放。
既有两个客户端、Lua 服务端、预测和独立进程结构属性测试同时运行新差量路径。
本轮未消除前后图像比较、临时候选值复制或完整实体存储成本，不把编码字节节省解释成相同比例的 CPU 节省。
