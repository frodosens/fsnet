# 客户端预测、确认与重放

本阶段提供显式输入预测机制，不改变服务端权限、mailbox、fencing 或提交后属性同步。
玩法转换仍由共享 Lua 方法实现；C++ 提供独立属性载体和执行限制。

## 使用合同

```lua
-- Actor 的 move(payload) 是确定性的共享方法；只修改 authority='driver'
-- 且实际出现在客户端投影中的属性。返回可选的效果描述字节串。
local confirmed = Actor:watch('alice')
local prediction = confirmed:prediction({max_inputs=128, max_bytes=262144})
local effect = prediction:push(1, 'move', '5')
-- 在 push 成功后，由调用方发送输入、播放声音/动画等；用输入序号标识效果。
-- push 本身不发送 RPC，不把客户端计算结果当成服务器状态。

-- 服务器提交输入后，将累计处理序号和对应状态一起同步。
-- 此处 processed_input 是业务声明的、只读且可见的服务器属性。
prediction:reconcile(confirmed.processed_input, confirmed.revision)
local displayed_x = prediction.state.x
local authoritative_x = prediction.confirmed.x
prediction:close()
confirmed:close()
```

服务器必须验证、按序处理输入，并将累计处理序号与权威状态放在同一次实体提交中。
拒绝的输入也需要明确确认其已处理；不要仅以 RPC 完成或属性版本猜测输入确认。
序号可编码在业务 payload 中，带请求 ID 的重试沿用实体回执去重合同。
框架不预设业务输入协议，也不自动发送或重试输入。

`push(sequence, method, bytes)` 默认从 1 开始接受连续整数序号，成功后返回一次方法结果。
已有累计序号时可在创建选项传入 `acknowledged=confirmed.processed_input`，后续从其加一开始；
该初始序号必须由与当前快照配套的服务器属性提供。
重复、跳号、队列满、字节超限或执行失败均拒绝，状态和历史保持不变。
每个控制器默认/最多保留 128 条输入、256 KiB 的方法名与 payload 字节；Lua 表及
原生状态另外计入 VM 内存预算。方法名最多 127 字节，payload 必须为不可变字节串。

`reconcile(ack_sequence, confirmed_revision)` 由应用收到确认后调用，要求版本**正好匹配
当前确认快照**，且不早于上次校正版本；确认序号不能倒退或超过成功提交的输入序号。
框架复制确认状态，按序重放所有大于 ack 的输入，成功后一次替换预测状态并移除已确认历史。
重复确认可安全重建相同结果。旧版本确认应忽略，等快照与确认匹配后重试；当同步已前进，
应使用新快照中配套的累计确认序号，不能把旧 ack 与新状态拼接。

确认副本始终独立、只读；`prediction.state` 是独立 userdata，仅在框架运行该输入时
允许写可见的 driver 属性。其他时候可以读属性/运行查询，直接赋值拒绝。
`prediction.revision` 是上次成功校正的确认版本；预测载体自身的 revision 只表示本地
属性变更，不能用于服务器写提案。`pending`、`acknowledged` 分别给出剩余输入数和累计确认序号。
每次 push/校正成功都会替换 state；旧的只读视图保留当时的属性，不会跟随控制器更新，
渲染时应重新读取 `prediction.state`。状态和历史通过一次引用替换发布，避免预算中断造成两者不一致。
执行错误时丢弃候选状态，保留原状态和历史；应用可重试校正或关闭后重新创建预测器。

## 副作用与确定性

首次预测与重放都禁止网络连接、RPC、订阅/写提案、等待、关闭对象、创建其他实体、
修改其他实体，以及 print/warn、环境随机数/随机种子。原生限制会记录违规，即使方法
用 pcall 吞掉错误，本次预测仍失败。限制在异常后恢复，不会污染后续正常网络调用。
预测方法在受控子协程运行，使指令预算耗尽可以直接让出并终止任务，不能被内部
pcall 死循环吞掉。现有每次 resume 的总指令预算和 VM 内存预算继续生效。

效果通过方法的返回字节串交给 `push` 调用方，只在第一次成功输入后处理；重放丢弃
这些返回值，从而不重复分发效果。失败的 push 不返回成功效果；同序号不能再成功 push。
这属于单个控制器内的有界去重，不提供跨重连/进程重启的外部 exactly-once 保证。

共享方法必须是确定性的属性转换，不能修改闭包/全局表、共享 context 或调用自行
保存的其他外部能力。当前 Lua VM 是可信脚本的错误隔离环境，不会回滚任意 Lua 堆
或隔离所有原生库。随机性应作为显式输入或声明属性中的确定性种子传入。

订阅撤销、断线或确认副本关闭后，预测状态访问也会拒绝，避免继续使用失效权限。
预测器 close 可重复，释放历史并关闭本地状态，不会关闭调用方持有的确认订阅。
重新连接需要重新 watch 并创建预测器；自动输入重发、渲染平滑、固定帧同步、Gateway
迁移和完整回滚世界不属于当前阶段。

## 验证

`fsnet-prediction` 使用真实 Node/属性同步与 Lua 客户端，覆盖权威校正与剩余输入重放、
重复/非法确认、输入限额、失败的原子回滚、吞错后的副作用拒绝、效果只交付一次、
私有属性/非 driver 属性限制、指令/分配预算失败后的恢复、订阅撤销和引擎停止后的内存清理。
`fsnet-prediction-process` 另用两个独立启动器执行随仓库交付的完整示例。
