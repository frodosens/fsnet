# 代码审查与设计结论

审查基线为 [原始版本](https://github.com/frodosens/fsnet/tree/69a4b62e52ff1874d25f7e64cdb176829f2024be)。
以下路径均指历史源码；旧实现已退出主线，新的测试结果不能作为旧代码已修复的证据。
本文保留与当前 C++/Lua 重构有关的网络核心结论。

## 原生网络问题

| 等级 | 历史位置 | 触发与影响 | 当前实现 |
| --- | --- | --- | --- |
| P1 | `FSNet/fs_node.c:169`、`fs_server.c:400` | 关闭时直接销毁 mutex/event_base，缺少线程 join 与状态所有权，可能与回调并发使用 | 连接状态由所属事件循环串行修改；关闭幂等，取消后检查状态 |
| P1 | `FSNet/fs_stream.c:188`、客户端 `fs_stream.c:197` | 使用 memcpy 压缩重叠缓冲区，弱引用缓冲可能被 realloc | 使用拥有明确生命周期的字符串/队列 |
| P1 | `FSNet/fs_server.c:780` | 固定长度数组上的 strcpy 缺少长度检查 | 字符串、帧、路由及队列均有长度上限 |
| P1 | `FSNet/fs_node.c:225` | 网络缓存无限扩张，缺少按客户端配额 | 有界帧长、连接数、发送队列、挂起调用与入站请求 |
| P2 | `client/.../FSClientBase.cpp:16`、`:90`、`:124` | hostname 固定拷贝不保证 NUL；close 不重置 fd；连接不检查 SO_ERROR；析构缺少资源释放 | 新 Node 通过 RAII、异步 error_code 与幂等清理管理连接；旧 SDK 不直接接入 |

这些问题来自静态审查和早期运行诊断，不能据此断言旧框架所有问题均已找到。

## 当前设计判断

C++ 只实现网络、分布式调度、实体载体与存储机制，玩法放在 Lua。网络只调用显式
注册的 RPC，不根据客户端提供的名称反射调用任意脚本方法；属性使用声明式 schema
进行类型、权限和同步范围校验。

单中心、随机实体路由、无持久化语义的内存状态不适合高可用。当前以 owner 路由、
租约/fencing、单记录 CAS、同实体串行 mailbox 和有界回执作为基础；真实跨机接管、
客户端 SDK、部署及长期容量仍按 [架构](ARCHITECTURE.md) 和 [路线图](ROADMAP.md) 验收。

旧协议与新协议不兼容。旧 C++ SDK 和客户端应用需要显式迁移，不能直接接入新节点。
