# Copy 优化实施与验证

基线为 `55de967`；[原始 review](PERFORMANCE_REVIEW.md) 描述优化前实现。
全部机制保持客户端/服务端共用，异步队列和重试请求继续拥有数据。

## 阶段一：同步借用边界

- 共用 FSE/FSS 借用解析器；原 owning API 在同一解析器上复制，保留独立生命周期。
- Gateway 路由只解析头，不复制业务 payload。
- Node::call 同步读取 string_view 并在返回前构造拥有数据的输出帧；发送队列继续持有帧。
- 内部实体状态移交给生命周期链，消除末次调用的条件表达式临时副本；封包按总大小 reserve。
- 使用自定义身份解析器时，不再先构造随后会被覆盖的证书指纹 subject。

普通 CTest 30/30 通过，新增输入销毁/覆盖后的异步发送、二进制借用解析和独立 owned 结果检查；
原 Router 回执重试、生命周期失败、预测与跨节点独立进程检查继续通过。
C++ Node::call 签名改变，嵌入方必须与新头文件一起重编，C ABI 和网络封包保持不变。

保存基线可执行文件及其 libfsnet.so，逐构建指定 LD_LIBRARY_PATH，预热后交替 A/B、B/A
三对，本机 Release / 明文 loopback / 并发32。不能混用新旧共享库。
[原始样本](benchmarks/copy-boundaries-2026-10-24.json)：64KiB direct 吞吐中位数
10,922 → 15,582 req/s；Gateway 6,727 → 7,132 req/s。128B/4KiB 没有稳定提升，
不将这些小幅波动描述为收益；大载荷少一次全值复制更容易被测到。
该实验未测TLS/持久化吞吐，也不把一次局部改善当作生产容量承诺。

```sh
python3 tools/compare_engine_benchmarks.py BEFORE_BUILD AFTER_BUILD --quick --runs 3 --output copy.json
```

## 阶段二：保留属性字节与共享确认版本

Gateway 的 watch 回复、属性通知、存在性通知和迁移快照均使用共用 replication codec：
完整 decode_attributes 校验仍执行一次，转发只改原缓冲中的8字节订阅ID，不再构造第二份
完整属性编码。大小、身份、版本、类型、深度/节点预算及非法字节拒绝规则保留。
这一步消除了重新编码，不宣称已消除校验时的临时属性树；后续若需要无分配扫描，应复用同一
语法实现并验证完全相同的拒绝行为。Node::notify 与 call 一样在返回前组好拥有数据的帧。

AttributeReplica 提供 `snapshot()`，返回 `shared_ptr<const AttributeUpdate>`。同一版本的
读取共享载体；有读者或副本持有旧版本时，后续写入先分离，旧版本保持不可变。没有读者时，
增量应用在完成校验和候选分配后更新现有载体。失败/gap 不发布新版本，reset/移动不破坏
外部已持有的版本。`values()` 返回的借用引用只保证到下一次成功 apply/reset；跨更新读取
应持有 snapshot。ClientScriptHost 不再维护第二份全量 images 缓存，直接取得共用副本的版本。

这是确认版本的共享和写时复制，**不是嵌套 AttributeValue 的持久化树**；旧版本被持有时，
仍可能复制整份属性集合。Lua模型/预测载体、权限、提交和持久化语义保持原有边界。
C++类布局与Node签名变化要求嵌入方全量重编，不支持只替换so并复用旧头文件编译的程序。

## 最终复测

以 `55de967` 对应的保存构建作基线，最终优化构建预热后交替 A/B、B/A 五对；
[全部样本与二进制哈希](benchmarks/copy-optimization-2026-10-24.json)。每次使用各构建自己的
共享库，测量期间没有并行编译或运行其他测试。以下为各轮指标的中位数，保留全部波动样本。

| 场景 | 优化前 | 优化后 | 解读 |
| --- | ---: | ---: | --- |
| 128B直连RPC，并发32 | 153,387 req/s | 152,808 req/s | 无稳定收益 |
| 128B Gateway RPC，并发32 | 72,856 req/s | 69,411 req/s | 本轮中位数低4.7%，样本区间重叠；不宣称收益 |
| 4KiB直连RPC | 130,571 req/s | 132,901 req/s | 小幅波动 |
| 4KiB Gateway RPC | 56,893 req/s | 57,397 req/s | 小幅波动 |
| 64KiB直连RPC | 10,717 req/s | 15,031 req/s | 本轮吞吐提高40.3% |
| 64KiB Gateway RPC | 6,596 req/s | 7,041 req/s | 本轮吞吐提高6.7% |
| 属性发布到1接收者 | 191.539 µs | 193.465 µs | 无稳定收益，早期观察到的改善未复现 |
| 属性发布到8接收者 | 423.666 µs | 313.331 µs | 中位数下降，范围重叠较大，不作稳定收益承诺 |
| 属性发布到32接收者 | 792.204 µs | 804.493 µs | 无稳定收益 |
| 原生32属性副本delta应用 | 0.813 µs | 0.844 µs | 增加约31ns，版本共享带来间接访问/引用检查成本 |
| 16字段逐次提交一轮 | 27.562 ms | 24.886 ms | 本轮中位数下降，调度波动较大 |
| 16字段batch提交一轮 | 2.966 ms | 2.992 ms | 基本持平 |

owning FSE parser小载荷曾在中间实现中多出包装开销，最终改成同一模板语法按结果类型直接
构造。128B中位数为19.812→21.046ns，4KiB为60.113→60.435ns，不把它描述为 owning
解析加速。生产借用解析器在本轮约2.5–2.9ns、零分配；只有适合借用的同步边界才使用它。

新增 `fsnet-replication-benchmark` 在同一个最终构建中，对64KiB字符串+128个结构元素进行
旧算法/新算法的局部对照（每轮2000次）：

| 局部机制 | 旧算法路径 | 新算法路径 | 耗时比 |
| --- | ---: | ---: | ---: |
| 完整校验并转发：decode+encode / validate+原字节重映射 | 73.133 µs | 27.628 µs | 2.65× |
| 更新后取得确认版本：额外全值clone / 共享snapshot | 16.117 µs | 2.698 µs | 5.97× |

这些局部对照不是两份独立服务器的吞吐比；快照场景不长期持有历史版本，长期持有时仍需COW。
不将这两个倍数推广成所有业务或完整网络链路的倍数。

最终源码普通CTest 30/30、ASan/UBSan 19/19通过。重新CPack并解压到其他目录，包内程序
通过1000轮mTLS文件持久化提交、SIGKILL接管、幂等回执重放、优雅交接和清理，
[交付报告](validation/copy-optimized-delivery-2026-10-24.json)记录实际二进制哈希。
完整串行持久化链路仍受1ms轮询、Lua、校验、TLS和磁盘提交影响，未证明有稳定吞吐收益。
没有改动轮询策略，也没有省略fsync、身份校验或回滚来换取性能。

本轮保留的成本：校验期间的属性树构建、持有旧版本时的全值COW、Lua模型刷新复制和存储
全值快照。后续可以分阶段评估无分配共用扫描器、嵌套值结构共享及事件驱动调度；不能跳过
异常原子性、旧版本存活和跨节点权限验证。
