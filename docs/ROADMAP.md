# 分阶段交付

分支：`refactor/script-runtime`。每个阶段形成可检查的改动，完成相关验证后 commit + push；不将未实现计划标为已交付。

| 阶段 | 范围 | 验收边界 |
| --- | --- | --- |
| 0：基础重构（当前提交） | 审查、CMake、网络 RPC、可替换存储、fencing、健康路由、Ruby 适配、ICE/TURN、测试 | 当前本机验证记录见 VALIDATION.md；不代表完整生产级框架 |
| 1：脚本宿主 | 小型通用宿主接口、Lua 首选适配器、Ruby 可选构建、消息/错误/协程边界 | 不加载脚本时核心独立运行；示例业务全部在脚本；两适配器执行共同宿主合同 |
| 2：场景与实体载体 | 单写者 mailbox、tick 调度、实体句柄、快照与恢复钩子、执行/内存预算 | C++ 不含玩法规则；并发、销毁、超时和脚本异常有测试 |
| 3：持久化与接管 | 异步存储执行器、生产数据库适配器、事务/幂等、fencing 与恢复编排 | 独立进程接管、旧 owner 写入拒绝、存储失败与重试边界 |
| 4：安全与 P2P 集成 | 加密、客户端身份与授权、认证信令、NAT/中继接入及配额 | 恶意请求与重放检查；真实跨 NAT 测试需要相应网络环境；明确 UDP 禁用时的能力边界 |
| 5：迁移与发布 | 旧版本归档、旧 C/旧 SDK 退出主线、部署与可观测性、故障/容量验证 | 无残留旧依赖；按可重复负载与故障场景验收，不以回环吞吐推算在线人数 |

阶段可根据实际依赖拆分为更小的提交。新的范围决定先写入架构文档，避免实现逐渐偏离“C++ 只提供载体，脚本实现业务”的目标。
